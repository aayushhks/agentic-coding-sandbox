# M15 — Framing & Deploy

The capstone: reframe the project around the deployment story and package it so the stakeholder view
is live — without hiding what's a stand-in.

## The reframe

The README now leads with the stakeholder problem — an engineering team's ticket queue — and the
deployment that works it: the agent, the MCP integration layer, the trust boundary, the
messy-ticket and injection handling, and the eval that proves it (including knowing when to
escalate). The technical depth (agent loop, sandbox, MCP conformance, eval harness) stays below the
fold, so the same README reads for a forward-deployed-engineering hiring manager and an AI-tools
team lead. The architecture diagram now shows both MCP servers, the trust boundary, and the
ticket → eval → report → dashboard flow.

## The MCP-client demo

The kickoff asked for a screenshot or GIF of a general-purpose MCP client connected to the sandbox
server. A GUI screenshot isn't reproducible from a headless build, so the honest substitute is a
**real recorded session**: [`mcp-session.md`](mcp-session.md), generated by
[`scripts/mcp_session_demo.py`](../scripts/mcp_session_demo.py), which spawns the sandbox server over
stdio with the MCP SDK client, completes the handshake, lists the tools, and calls them — including
the workspace jail rejecting an absolute path. It regenerates with one command.

## Deploy packaging

- **The image bakes the ticket-eval report** (`docs/results/tickets-reference.json` is added to the
  Dockerfile COPY), so `GET /api/deployment-report` and the dashboard's report tab work in the
  deployed container. `deployment_report_path` points at it by default and is overridable.
- **Static export for no-backend hosting.** The report is also copied into the SPA
  (`frontend/public/deployment-report.json` → `dist/deployment-report.json`), and the frontend
  client falls back to it when the API isn't reachable — so the stakeholder deployment report can
  be served from a pure-static host (S3 + CloudFront) with no always-on backend. The full dashboard
  (benchmark runs / compare) still needs the API.
- **The MCP servers are not exposed publicly.** They run locally over stdio; the deployment shows
  their recorded results, not a live tool endpoint.

## The one manual step

This build environment can't reach the running EC2 instance, so picking up new code on the live box
is a manual redeploy (the same command as [m10](m10-deploy.md)), run on the instance:

```bash
cd agentic-coding-sandbox && git pull
sudo docker build -t agentic-coding-sandbox . \
  && sudo docker rm -f acs \
  && sudo docker run -d --name acs -p 80:8000 --restart unless-stopped agentic-coding-sandbox
```

Until then the live site serves the previous image; CI stays green because the live-site smoke test
checks `/health` and `/api/runs`, which are unchanged.

## Honest notes

- The reframe changes no behavior — it is framing plus deploy packaging.
- The rendered report remains the scripted reference until a real-model eval is run and its JSON is
  committed / baked in its place.
